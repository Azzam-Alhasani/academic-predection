How the model was chosen

{{ study.classification.planning.candidates|length }} candidate models were compared on {{ study.meta.n_students }} simulated course attempts of {{ study.meta.n_people }} students (a random sample of {{ study.meta.population_rows }} graded attempts) (failure rate {{ '%.1f'|format(study.meta.fail_rate * 100) }}%; a student's courses are always kept on the same side of every test split) with the same evaluation rules.

  1. Fair scoring. {{ study.meta.cv.splits }}-fold cross-validation repeated {{ study.meta.cv.repeats_stage_a }} times: every student is scored by a model that never saw them, and every model sees identical splits.
  2. Tuning without leakage. The strongest models were tuned with nested cross-validation: settings are chosen on training data only and scored on students the tuning never saw, so tuning cannot inflate the result.
  3. Testing the differences. Corrected paired t-tests (Nadeau & Bengio) compare each model with the best; p < 0.05 means "really worse", otherwise "tied".
  4. Decision rule. Highest mean ROC-AUC; if models are within one standard error, the simpler one wins.
The records are simulated. Accuracy here shows the pipeline works on data shaped like a transcript; it is not evidence of accuracy on real UTAS students. The attendance and course-difficulty effects are assumptions built into the simulator, so a model that finds them has learned the simulator.

Conclusions and limits
{% set c1 = (study.classification.planning.tuned|selectattr('key', 'equalto', study.classification.planning.selected)|list)[0] %} {% set c2 = (study.classification.during.tuned|selectattr('key', 'equalto', study.classification.during.selected)|list)[0] %} {% set base = (study.classification.planning.candidates|selectattr('key', 'equalto', 'majority')|list)[0] %}
  • Target accuracy (85% or more). Met on this data: about {{ '%.0f'|format(c1.metrics.accuracy.mean * 100) }}% at registration and {{ '%.0f'|format(c2.metrics.accuracy.mean * 100) }}% during the semester. But always predicting "passes" already scores {{ '%.0f'|format(base.metrics.accuracy.mean * 100) }}%, because only {{ '%.0f'|format(study.meta.fail_rate * 100) }}% of attempts fail. Accuracy alone flatters the model, so look at ROC-AUC ({{ pm(c1.metrics.roc_auc) }} and {{ pm(c2.metrics.roc_auc) }}).
  • Many failures are missed. At the default 50% alert level only about {{ '%.0f'|format(c2.metrics.recall.mean * 100) }}% of attempts that end in F are flagged even with attendance known ({{ '%.0f'|format(c1.metrics.recall.mean * 100) }}% at registration). Lowering the alert level to 30% catches more (see the threshold table) at the price of more false alarms.
  • What matters. Prior CGPA is the strongest input; attendance comes next once the semester has started; the course itself adds a little. Gender is not a model input.
  • Several models are statistically tied (p > 0.05), so the simplest, logistic regression (which can also be explained), is chosen for the fail chance; ridge regression is chosen for the mark.
  • Simulated data. The attendance effect, course difficulty and noise are set by the simulator (app/data/generate_students.py), so these figures describe the simulator. Retrain on anonymised real transcripts in the same CSV format with python -m app.ml.model_selection before relying on any number.
